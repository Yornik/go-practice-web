When it breaks, you get the reason

The site does not stop at "error at line 120". It names each part of the message and explains the rule behind it.

How you work an exercise

The steps come from the course itself. The site keeps the time, the runs and the hints in your learning log.

  1. Read the spec twice. Then read the tests. Their names tell you what "done" means.
  2. Work 2 examples by hand. Write down the state your code keeps and what must stay true about it.
  3. Pass 1 test first. Write the simplest code that can pass it. Run only that step.
  4. Read each failure. The site names every part of the message and explains the rule behind it.
  5. Stuck for 25 minutes? Reveal hint 1. Wait 10 minutes before the next hint.

The rules

  1. Do not use an LLM. That includes chat assistants and AI autocomplete. The editor has none.
  2. Use the documentation freely: go doc, pkg.go.dev, the Go spec, the Go blog and RFCs. The editor shows the standard library docs when you hover a name.
  3. Try for at least 25 minutes before you reveal hint 1. Wait at least 10 minutes between hints.
  4. If you read the reference solution, close it, wait, and write your own version from memory.
  5. After you pass, read the explanation and the walkthrough. They show the trade-offs.
